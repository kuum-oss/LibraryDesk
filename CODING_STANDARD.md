# Стандарт кодування LibraryDesk

**Самостійна робота № 1 · варіант 2 · версія 1.0.0 · чинний з 06.10.2026**

## 1. Сфера дії та глосарій

Власник стандарту — команда LibraryDesk; пропозицію може подати будь-який учасник. Стандарт поширюється на `LibraryDesk.Core`, `LibraryDesk.App` і майбутні тести. Не поширюється на `bin/`, `obj/`, згенерований код та гілку `sandbox`. Ідентифікатори англійською, документація українською.

Рівні: **ОБОВ’ЯЗКОВО** — порушення зупиняє збірку або PR не приймається; **РЕКОМЕНДОВАНО** — потрібна причина у PR; **ДОПУСКАЄТЬСЯ** — обидва варіанти прийнятні; **ЗАБОРОНЕНО** — конструкція не використовується. Формат: `ID — формулювання — рівень — обґрунтування — приклад — перевірка`.

| Поняття | Ідентифікатор | Пояснення |
|---|---|---|
| бібліотека | Library | фонд системи |
| книга | Book | одиниця фонду |
| ISBN | Isbn | код книги |
| читач | Reader | користувач фонду |
| читацький квиток | ReaderId | ідентифікатор читача |
| абонемент | Membership | право користування |
| видача | Loan | документ видачі |
| позиція видачі | LoanItem | книга і строк у документі |
| статус видачі | LoanStatus | стан життєвого циклу |
| активна видача | Active | книги ще не повернено |
| повернення | Returned | книги повернено |
| прострочення | Overdue | кінцева дата минула |
| скасування | Cancelled | видачу анульовано |
| втрата | Lost | книга втрачена |
| дата видачі | IssuedAt | момент створення |

## 6. Машинна частина

Кореневі `.editorconfig` і `Directory.Build.props` вмикають nullable, Roslyn, StyleCop, XML-документацію, `EnforceCodeStyleInBuild` і `TreatWarningsAsErrors`. Перед PR:

```bash
dotnet format --verify-no-changes
dotnet build -warnaserror
```

Обґрунтовані придушення: `SA1633` — навчальному проєкту не потрібен ліцензійний заголовок; `SA1309` — команда використовує `_camelCase`, що узгоджується з runtime; `SA1200` — using на початку та file-scoped namespace є свідомим рішенням. Кожне має коментар у `.editorconfig`.

Єдиний технічний борг аналізаторів, що залишився в конфігурації, — `CA1305` у успадкованому `Order.cs`. Він має запис `TD-001` у [`docs/self-work-01/TECHNICAL_DEBT.md`](docs/self-work-01/TECHNICAL_DEBT.md), відповідального, план погашення та статус. Нові suppression без запису в реєстрі заборонені.

Для демонстрації перейменування `_items` на `items` дає IDE1006/error; повернення `_items` дає `0 Warning(s), 0 Error(s)`. Знімки — `docs/self-work-01/build-before.txt` і `build-after.txt`.

## 7. Чекліст, порівняння, порядок змін

Людський чекліст — [`docs/self-work-01/CODE_REVIEW_CHECKLIST.md`](docs/self-work-01/CODE_REVIEW_CHECKLIST.md), журнал — [`docs/self-work-01/DECISIONS.md`](docs/self-work-01/DECISIONS.md). Чекліст не дублює форматування та naming, які перевіряє машина.

| Питання | Microsoft Learn | dotnet/runtime | LibraryDesk | Чому |
|---|---|---|---|---|
| Відступ | 4 пробіли | 4 пробіли | 4 пробіли | читабельність |
| Дужки | Allman | Allman, інколи без braces | завжди braces | захист від додавання другого оператора |
| Приватне поле | `_camelCase` | `_camelCase`, static `s_` | те саме | видно стан об’єкта |
| `var` | коли тип очевидний | за замовчуванням IDE | лише очевидний справа | баланс ясності |
| Довжина | рекомендація 65 у прикладах | без жорсткої межі | 100 | side-by-side diff |
| using | стандарт IDE | стандарт IDE | System першими | стабільний diff |
| namespace | загальний стиль | сучасний стиль | file-scoped | менше шуму |
| порядок членів | не жорсткий | конвенція | const → поля → API | швидкий пошук |
| XML | public API | public API | весь Core API | контракт бібліотеки |
| const | PascalCase | PascalCase | PascalCase | .NET-сумісність |
| Async | `Async` | `Async` | `Async` | чесний контракт await |
| nameof | рекомендовано | рекомендовано | обов’язково в повідомленнях | безпечний refactor |
| region | обережно | не для структури | заборонено | не приховуємо великий тип |
| дати | за значенням | за значенням | DateOnly/DateTimeOffset | різна семантика |

Три свідомі відступи: braces завжди, хоча runtime допускає один оператор; 100 символів, хоча runtime не має межі; `DueDateExclusive` і `today`, яких немає у загальному стилі. Причина кожного — менша ціна дефекту на межі або під час рев’ю.

### Порядок внесення змін

1. Будь-хто створює PR із ID, правилом, рівнем, обґрунтуванням, прикладами, перевіркою та оцінкою міграції.
2. Двоє учасників оцінюють користь, вартість і предметну сумісність.
3. Більшість ухвалює рішення; власник оновлює документ, конфіги й журнал.
4. Рішення отримує номер і дату в `DECISIONS.md`.
5. SemVer: patch — уточнення, minor — необов’язкове правило, major — підвищення рівня.
6. Перехідний період — 14 днів; діє правило бойскаута для змінених файлів.
7. Шкідливе правило скасовують новим ADR, тестом і видаленням enforcement.
