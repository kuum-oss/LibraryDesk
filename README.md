# LibraryDesk

[![CI](https://github.com/kuum-oss/LibraryDesk/actions/workflows/ci.yml/badge.svg)](https://github.com/kuum-oss/LibraryDesk/actions/workflows/ci.yml)

LibraryDesk — консольний застосунок .NET 8 для обліку видачі та повернення книг, розрахунку пені й формування звіту про боржників.

## 1. Навчальна робота

- **Варіант:** 2 — LibraryDesk.
- **Виконав:** Гордєєв Дмитро.
- **Група:** 472.
- **Дисципліна:** «Конструювання програмного забезпечення».
- **Робота:** СР-3 «Індивідуальний проєкт: конструювання застосунку за варіантом».

## 2. Швидкий старт

Потрібні Git і .NET SDK 8.0. У порожній теці виконайте рівно три команди:

```bash
git clone https://github.com/kuum-oss/LibraryDesk.git && cd LibraryDesk
dotnet build LibraryDesk.sln -c Release
dotnet run --project LibraryDesk.App/LibraryDesk.App.csproj -c Release
```

Під час першого запуску застосунок створює локальний навчальний набір із 50 книг і 20 умовних читачів. Реальні персональні дані не використовуються.

## 3. Структура рішення

- `LibraryDesk.Core` — домен, прикладні сценарії, інтерфейси залежностей, правила строку й пені, JSON-адаптер і журнал.
- `LibraryDesk.App` — консольне меню та композиційний корінь; розрахунків і правил тут немає.
- `LibraryDesk.Tests` — модульні, параметризовані, архітектурні та інфраструктурні тести.
- `src/Legacy` і `tests/Legacy.Tests` — ізольований навчальний модуль попередньої роботи з характеризаційними тестами; робочий застосунок від нього не залежить.
- `docs` — специфікація, архітектура, посібник, журнал рішень, самооцінка та матеріали лабораторних робіт.

Напрям залежностей і точки розширення пояснено в [архітектурі](docs/architecture.md).

## 4. Можливості

Повні передумови, альтернативи й постумови наведено у [специфікації](docs/spec.md).

- [UC-01](docs/spec.md#uc-01-зареєструвати-книгу) — зареєструвати книгу або поповнити кількість примірників.
- [UC-02](docs/spec.md#uc-02-зареєструвати-читача) — зареєструвати умовного читача.
- [UC-03](docs/spec.md#uc-03-видати-книжку) — видати доступну книгу на 14 календарних днів.
- [UC-04](docs/spec.md#uc-04-прийняти-повернення) — прийняти повернення та обчислити пеню.
- [UC-05](docs/spec.md#uc-05-знайти-формуляри) — знайти формуляри за читачем і станом.
- [UC-06](docs/spec.md#uc-06-сформувати-звіт-боржники-на-дату) — сформувати впорядкований звіт «Боржники на дату».

Профільне правило: до 7 днів прострочення діє базова денна ставка; з 8-го дня — множник 1,5; пеня округлюється до копійок і не перевищує вартості заміни книги.

## 5. Тести й покриття

Повна локальна перевірка, еквівалентна CI:

```bash
./tools/verify.sh
```

Скрипт відновлює залежності, перевіряє формат, збирає Release з `--warnaserror`, запускає всі тести, збирає Cobertura та перевіряє поріг 70%. Поточний відтворений результат:

- 97 зелених тестів: 85 основного рішення і 12 ізольованого Legacy-модуля;
- рядкове покриття домену та прикладної логіки — **85,31%**;
- покриття гілок — **71,62%**.

Межу вимірювання зафіксовано у [`docs/sr03/coverlet.runsettings`](docs/sr03/coverlet.runsettings), аналіз непокритих гілок — у [`docs/sr03/coverage-analysis.md`](docs/sr03/coverage-analysis.md).

## 6. Технології та критерії якості

- .NET 8 і C# 12;
- xUnit, `coverlet.collector` і Cobertura;
- Roslyn .NET analyzers і StyleCop.Analyzers;
- nullable reference types, XML-документація й `TreatWarningsAsErrors`;
- GitHub Actions для кожного push і pull request до `main`;
- System.Text.Json без зовнішньої бази даних.

CI зупиняється через відхилення формату, попередження компілятора, червоний тест або рядкове покриття нижче 70%. Звіт покриття зберігається як артефакт прогону.

## 7. Дані, журнал і резервна копія

Робочі файли створюються в `data/` відносно каталогу запуску:

- `data/library.json` — каталог, читачі та формуляри;
- `data/librarydesk.log` — час, рівень, сценарій і технічне повідомлення без паролів та вмісту файлів.

Для резервної копії завершіть застосунок і скопіюйте `data/library.json`. Детальні сценарії наведено у [посібнику користувача](docs/user-guide.md).

## 8. Обмеження й відомий борг

Застосунок однокористувацький і записує весь JSON-знімок цілком, тому не розрахований на одночасну роботу кількох процесів або десятки тисяч записів. Авторизації, GUI, вебдоступу, бази даних і онлайн-оплати немає — це свідомі межі варіанта. Ізольований Legacy-модуль лишено для доказів попереднього аудиту, тому загальний обсяг репозиторію більший за продуктове ядро. Формальне вимірювання цикломатичної складності ще не автоматизоване, а історія на поточну дату охоплює чотири замість шести різних днів. Деталі та оцінки наведено в [самооцінці](docs/self-check.md).
