# Завдання 5 Ручний фейк і стаб

`LoanService` уже отримує `ILoanRepository`, `IPricingPolicy`, `INotifier` і
журнал через конструктор, тому його можна тестувати без файлової системи чи
бази даних. `FakeLoanRepository` зберігає об'єкти у словнику, а
`StubPricingPolicy` повертає одну наперед задану ціну для кожної позиції.

| Ознака | Стаб ціни | Фейк сховища |
|---|---|---|
| Внутрішній стан | лише налаштована відповідь | словник виданих формулярів |
| Що повертає | ту саму ціну для кожної позиції | об'єкт, доданий через `Add` |
| Поведінка | задає вхід для підсумовування | імітує робоче сховище в пам'яті |
| Коли доречний | потрібна передбачувана відповідь | код записує, а потім читає дані |

В інтерфейсі цього проєкту немає окремого `Save`, тому замість `SaveCalls`
фейк має `AddCalls`. Лічильник перевіряє взаємодію із залежністю й наближає
фейк до мока або шпигуна, хоча основна його роль залишається сховищем у
пам'яті.

Три тести перевіряють підсумовування двох заданих стабом цін, реєстрацію
активної видачі у фейку рівно одним викликом та помилку пошуку невідомого
ідентифікатора. Якби сервіс надсилав реальний лист, для перевірки адресата й
тексту повідомлення знадобився б мок або шпигун `INotifier`: важливим був би
сам факт виклику з правильними аргументами, а не повернене значення.
