# Посібник користувача LibraryDesk

## 1. Запуск і перший екран

У корені репозиторію виконайте:

```bash
dotnet run --project LibraryDesk.App/LibraryDesk.App.csproj -c Release
```

Після першого запуску з’являється версія і меню:

```text
LibraryDesk v1.0.0

1 — зареєструвати книгу
2 — зареєструвати читача
3 — видати книжку
4 — прийняти повернення
5 — знайти формуляри
6 — звіт «Боржники на дату»
0 — завершити
Ваш вибір:
```

Якщо `data/library.json` відсутній, програма автоматично створює 50 книг `ISBN-0001`–`ISBN-0050` і 20 умовних читачів. Повторний запуск завантажує збережений стан і не дублює записи.

## 2. Прохідні сценарії

### 2.1. UC-01 — додати нову книгу

```text
Ваш вибір: 1
ISBN: ISBN-9001
Назва: Конструювання програмного забезпечення
Денний тариф: 12.50
Вартість заміни: 850
Кількість примірників: 2
Збережено: Конструювання програмного забезпечення.
```

Повторне введення того самого ISBN не створює дубль, а додає вказану кількість до доступного залишку.

### 2.2. UC-02 — додати читача

```text
Ваш вибір: 2
Ідентифікатор: 101
Ім'я: Тестовий читач 101
Email: reader101@example.com
Збережено читача № 101.
```

Використовуйте лише умовні дані. Реальні адреси, номери документів або паролі у навчальний файл не вводяться.

### 2.3. UC-03 — видати книгу

Для прикладу використано читача `1` і книгу `ISBN-0001`, які створені автоматично.

```text
Ваш вибір: 3
Номер формуляра: 1001
Номер читача: 1
ISBN: ISBN-0001
Книгу видано. Повернути до 24.10.2026.
```

Дата залежить від дня запуску: система додає 14 календарних днів через замінний годинник. Кількість доступних примірників зменшується на один, а формуляр переходить `Draft → Active`.

### 2.4. UC-05 — знайти активні формуляри читача

```text
Ваш вибір: 5
Номер читача (Enter — усі): 1
Стан англійською (Enter — усі): Active
#1001; читач 1; до 24.10.2026; Active
```

Порожнє значення критерію означає «усі». Допустимі стани: `Draft`, `Active`, `Overdue`, `Returned`, `Cancelled`, `Lost`. Результат упорядковано за строком, потім за номером формуляра.

### 2.5. UC-04 і UC-06 — повернення та звіт

Якщо формуляр повертається через 8 днів після строку, діє підвищений множник 1,5:

```text
Ваш вибір: 4
Номер формуляра: 1001
Дата повернення (рррр-мм-дд): 2026-11-01
Повернення прийнято. Днів прострочення: 8; пеня: 72.00 грн.
```

Для `ISBN-0001` денна ставка дорівнює 6,00 грн, тому `8 × 6,00 × 1,5 = 72,00 грн`. Після повернення примірник знову доступний, а формуляр має стан `Returned` і більше не потрапляє до звіту боржників.

Звіт до повернення формується так:

```text
Ваш вибір: 6
Дата звіту (рррр-мм-дд): 2026-11-01
БОРЖНИКИ НА 01.11.2026
#1001; Тестовий читач 1; 8 дн.; 72.00 грн
```

## 3. Повідомлення про помилки

| Повідомлення | Причина | Що зробити |
|---|---|---|
| `Очікується ціле число` | Для ідентифікатора або кількості введено текст | Повторно вибрати пункт меню й увести ціле число |
| `Використайте число з крапкою` | Тариф або вартість мають неправильний формат | Увести, наприклад, `12.50` |
| `Дата має формат рррр-мм-дд` | Дату не розпізнано | Увести, наприклад, `2026-11-01` |
| `Читача або книгу не знайдено` | Немає одного з довідникових записів | Перевірити ідентифікатор та ISBN |
| `Потрібен активний абонемент і доступний примірник` | Абонемент неактивний або залишок нульовий | Активувати абонемент поза межами версії 1.0 або обрати іншу книгу |
| `Формуляр із таким ідентифікатором уже існує` | Номер не унікальний | Увести інший номер формуляра |
| `Операцію заборонено` | Стан формуляра не допускає перехід | Перевірити формуляр пошуком і виконати дозволений сценарій |

Некоректний ввід не завершує програму: після повідомлення вона повертається до меню. Пошкоджений JSON або помилка доступу до диска вважаються технічним збоєм, записуються на рівні Error і завершують запуск, щоб не продовжувати роботу з неповними даними.

## 4. Дані, журнал і резервна копія

Файли лежать у теці `data` поточного каталогу:

- `library.json` — робочий стан;
- `librarydesk.log` — структурований журнал сценаріїв.

Для резервної копії:

1. Завершіть застосунок пунктом `0`.
2. Скопіюйте `data/library.json` у безпечне місце.
3. Для відновлення замініть файл копією до запуску програми.

Не редагуйте JSON під час роботи програми. Якщо файл видалити, наступний запуск створить новий початковий набір; попередні формуляри при цьому буде втрачено.
