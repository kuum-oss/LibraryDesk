# Рішення щодо повернення null

| Метод | Поточна семантика | Рішення | Обґрунтування |
|---|---|---|---|
| `ILoanRepository.GetById(int)` | Повертає `Loan?`, якщо запису немає | Залишити | На рівні репозиторію відсутність запису є нормальним результатом пошуку; nullable-контракт явно це показує |
| `InMemoryLoanRepository.GetById(int)` | Реалізує nullable-пошук | Залишити | Реалізація має відповідати контракту `ILoanRepository` і не вирішує бізнес-правила виклику |
| `LoanService.GetRequiredLoan(int)` | Потрібен наявний формуляр для бізнес-операції | Не повертати `null`; кидати `DomainRuleException` | Сервіс додає контекст правила `loan.exists`, і викликач не може випадково проігнорувати відсутній формуляр |

Таким чином, `null` залишається тільки на межі запиту до сховища. У сценаріях, де подальша операція вимагає наявного формуляра, сервіс одразу перетворює відсутність запису на предметний виняток із конкретним ідентифікатором.
