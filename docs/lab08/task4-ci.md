# Завдання 4. Конвеєр безперервної інтеграції

Workflow `.github/workflows/ci.yml` запускається для кожного push у `main`
та `feature/**`, а також для pull request у `main`.

| Крок | Команда або дія | Що зупиняє конвеєр |
|---|---|---|
| Відновлення | `dotnet restore LibraryDesk.sln` | неможливо відновити залежність або аудит NuGet |
| Формат | `dotnet format --verify-no-changes` | файл потребує форматування |
| Складання | `dotnet build -c Release` | будь-яке попередження або помилка CS, CA, SA |
| Тести | `dotnet test -c Release` | хоча б один невдалий тест |
| Покриття | `/p:Threshold=60` | покриття рядків нижче 60% |
| Артефакт | `actions/upload-artifact@v4` | звіт зберігається навіть після збою попереднього кроку |

Форматування стоїть перед складанням, тому що це швидша перевірка: якщо
відступи або порядок `using` порушені, конвеєр завершується до витрат часу
на компіляцію й тести.

Локальна перевірка дала 67,78% покриття рядків `LibraryDesk.Core`, тому
поріг 60% не знижувався. Після публікації гілки потрібно зберегти посилання
та знімок зеленого запуску зі списком кроків.
