## 1. Мета роботи

Перетворити метод-монстр розрахунку вартості формуляра на набір коротких підпрограм із функціональною зв’язністю, додати захисні перевірки передумов, застосувати Introduce Parameter Object, відокремити чисті функції від побічних ефектів і підтвердити покращення метриками та тестами.

## 2. Підготовка та характеризаційні тести

Для фіксації початкової поведінки створено `LibraryDesk.Core/Legacy/LegacyProcessor.cs` і `LibraryDesk.Core/Legacy/LoanLine.cs`. Метод зберігає структуру еталонного методу-монстра: 11 параметрів, перевірки, цикл, знижки, зміну статусу та друк у консоль.

Приклад початкового рядка:

```csharp
decimal total = LegacyProcessor.Process(
    1, "Іваненко", "i@ex.com", true, lines,
    new DateOnly(2026, 3, 10), "", "Active", false, 60m,
    out string next);
```

Характеризаційні тести зафіксували три результати:

| Сценарій | Очікуваний результат |
|---|---:|
| постійний читач, 12 днів по 100 і 1 день по 250 | `1292,70`, статус `Returned` |
| мала видача з купоном і доставкою | `420,00`, статус `Overdue` |
| порожній список книжок | `-1` |

Ручний розрахунок першого тесту:

1. Книжка A1: `12 × 100 = 1200`; гуртова знижка 5%: `1200 × 0,95 = 1140`.
2. Книжка B2: `1 × 250 = 250`.
3. Підсумок позицій: `1140 + 250 = 1390`.
4. Знижка постійному читачеві 7%: `1390 × 0,93 = 1292,70`.
5. Інші знижки та доставка не застосовуються, результат після округлення — `1292,70`.

Команда проверки:

```text
Пройдено: 0, пройдено 3, пропущено 0, всего 3
```

## 4. Захисне програмування

У `DocumentGuards` м’яке повернення `-1` замінено на швидке завершення з винятком. Неприпустимий стан тепер не маскується магічним числом, а причина помилки доступна виклику.

```csharp
public static void EnsureLineValid(LoanItem item)
{
    ArgumentNullException.ThrowIfNull(item);
    ArgumentException.ThrowIfNullOrWhiteSpace(item.Isbn);
    ArgumentOutOfRangeException.ThrowIfNegativeOrZero(item.Days, nameof(item.Days));
    ArgumentOutOfRangeException.ThrowIfNegative(item.DailyRate, nameof(item.DailyRate));
}
```

| Передумова | Виняток |
|---|---|
| `loanId <= 0` | `ArgumentOutOfRangeException` |
| `readerName` порожній або пробільний | `ArgumentException` |
| `readerEmail` порожній або пробільний | `ArgumentException` |
| пошта не містить `@` | `ArgumentException` |
| `items == null` | `ArgumentNullException` |
| список книжок порожній | `ArgumentException` |
| `item == null` | `ArgumentNullException` |
| `Days <= 0` | `ArgumentOutOfRangeException` |
| `DailyRate < 0` | `ArgumentOutOfRangeException` |
| `deliveryPrice < 0` | `ArgumentOutOfRangeException` |

Повернення `-1` гірше за виняток, бо виклик не може надійно відрізнити помилку вхідних даних від коректної грошової суми.

## 5. Декомпозиція та Introduce Parameter Object

Замість 11 окремих аргументів створено незмінний record `LoanCalculationRequest`. Результат також повертається типом `LoanTotalResult`, а не через `out`.

```csharp
public sealed record LoanCalculationRequest(
    int LoanId,
    string ReaderName,
    string ReaderEmail,
    bool IsRegularReader,
    IReadOnlyList<LoanItem> Items,
    DateOnly IssuedOn,
    string? CouponCode,
    LoanStatus Status,
    decimal DeliveryPrice);
```

| Підпрограма | Єдина відповідальність | Параметрів | ЦС |
|---|---|---:|---:|
| `SubtotalOf` | сума книжкових позицій і гуртова знижка | 1 | 3 |
| `ReaderDiscountOf` | знижка постійному читачеві | 2 | 2 |
| `VolumeDiscountOf` | знижка за обсягом суми | 1 | 3 |
| `CouponDiscountOf` | знижка за кодом купона | 2 | 4 |
| `WeekendDiscountOf` | знижка за днем видачі | 2 | 2 |
| `DeliveryFeeOf` | плата за доставку | 2 | 2 |
| `NextStatusOf` | визначення наступного статусу | 2 | 3 |
| `Calculate` | оркестрація підпрограм у незмінному порядку | 1 | 2 |

Порядок обчислень збережено: спочатку підсумок книжок, потім знижка постійного читача, знижка за сумою, купон, вихідний день, доставка та округлення.

## 6. Чисті функції та CQS

Методи `SubtotalOf`, `ReaderDiscountOf`, `VolumeDiscountOf`, `CouponDiscountOf`, `WeekendDiscountOf`, `DeliveryFeeOf`, `NextStatusOf` і `Calculate` залежать тільки від своїх аргументів, не пишуть у консоль і не змінюють стан формуляра. Це запити.

Консольний застосунок окремо виконує команду виведення:

```csharp
LoanTotalResult result = DocumentTotalCalculator.Calculate(request);
Console.WriteLine($"Разом: {result.Total}");
Console.WriteLine($"Наступний стан: {result.NextStatus}");
```

Отже, розрахунок можна використати у вебзастосунку або тесті без перехоплення `Console.Out`.

## 10. Відповіді на контрольні питання

1. **Чому цикломатична складність важлива?** Вона показує кількість незалежних шляхів виконання. Для методу-монстра зі значенням 31 потрібно щонайменше 31 тестовий маршрут для покриття всіх гілок, тому такий метод важко перевіряти та змінювати.
2. **Чим чиста функція відрізняється від команди?** Чиста функція повертає результат і не змінює зовнішній стан. Команда змінює стан або виконує побічний ефект і не використовується як обчислювальний запит. У цій роботі калькулятор є запитом, а друк у консоль залишається на межі застосунку.
